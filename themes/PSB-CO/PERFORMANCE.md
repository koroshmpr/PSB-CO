# کارایی و صفحه ورود مدیریت (جایگزین افزونه Perfmatters)

از این نسخه، کارهایی که افزونه **Perfmatters** روی سایت انجام می‌داد داخل خود قالب انجام می‌شود و می‌توانید افزونه را حذف کنید.
بررسی تنظیمات نشان داد Perfmatters فقط برای **تغییر نشانی ورود مدیریت** استفاده می‌شد؛ بقیه بخش‌های آن (مدیریت اسکریپت، Preload، Lazy Load، فونت، CDN، آنالیتیکس و زمان‌بندی پاک‌سازی دیتابیس) خاموش بودند یا قبلاً در قالب انجام می‌شدند.

فایل‌ها:

- `theme/inc/login-guard.php`: نشانی اختصاصی ورود مدیریت
- `theme/inc/performance.php`: سبک‌سازی چند فایل اضافه و پاک‌سازی هفتگی دیتابیس
- `theme/inc/optimize.php` و `theme/inc/stability.php`: بهینه‌سازی‌هایی که از قبل در قالب بودند

---

## ۱. ورود به پیشخوان

- نشانی ورود: **`https://psb.co.ir/secret-door/`** (همان نشانی قبلی؛ نشانه‌گذاری (Bookmark) فعلی شما همچنان کار می‌کند)
- `/wp-login.php` و `/wp-admin/` برای کسی که وارد نشده صفحه «۴۰۴ — پیدا نشد» نشان می‌دهند. این رفتار عمدی است.
- بعد از ورود، `/wp-admin/` به‌طور عادی کار می‌کند.
- فراموشی رمز، خروج، تأیید ایمیل و Wordfence 2FA همه از همین نشانی انجام می‌شوند. لینک داخل ایمیل بازیابی رمز هم به همین نشانی اشاره می‌کند.
- این صفحه‌ها مثل قبل کار می‌کنند: ورود مشتری‌ها در `/login/` (کد یکبارمصرف)، پنل موبایل `/panel/` و حساب کاربری ووکامرس.

## ۲. تغییر نشانی ورود

۱. وارد پیشخوان شوید و به **تنظیمات › همگانی** بروید.
۲. در ردیف **«نشانی ورود مدیریت»** نشانی تازه را بنویسید. فقط حروف انگلیسی، عدد و خط تیره، و دست‌کم ۴ حرف.
۳. «ذخیرهٔ تغییرات» را بزنید و **نشانی تازه را فوراً نشانه‌گذاری کنید**. از همین لحظه نشانی قبلی ۴۰۴ می‌دهد.

نکته‌ها:

- نشانی‌هایی مثل `login`، `admin`، `panel`، `shop` و نامک برگه‌ها و نوشته‌های موجود پذیرفته نمی‌شوند.
- تا وقتی Perfmatters فعال است این فیلد فقط‌خواندنی است، چون نشانی را Perfmatters کنترل می‌کند.
- برای تعیین نشانی از طریق فایل، این خط را در `wp-config.php` بگذارید. با این کار فیلد تنظیمات قفل می‌شود:

```php
define( 'PSB_LOGIN_SLUG', 'secret-door' );
```

## ۳. اگر وارد نشدید (حالت اضطراری)

این راه از طریق FTP یا File Manager هاست انجام می‌شود:

۱. فایل `wp-config.php` را در پوشه اصلی سایت (`public_html`) باز کنید.
۲. **بالای** خط `/* That's all, stop editing! */` این خط را اضافه کنید:

```php
define( 'PSB_LOGIN_GUARD_DISABLE', true );
```

۳. ذخیره کنید. حالا ورود از نشانی عادی `https://psb.co.ir/wp-login.php` کار می‌کند.
۴. بعد از حل مشکل، **این خط را دوباره پاک کنید** تا صفحه ورود باز هم مخفی شود.

اگر نشانی را فراموش کرده‌اید، در جدول `wp_options` مقدار `psb_login_slug` را ببینید (phpMyAdmin)، یا از راه بالا وارد شوید و در «تنظیمات › همگانی» آن را ببینید.

## ۴. جابه‌جایی از Perfmatters (یک‌بار، بعد از استقرار قالب)

۱. قالب جدید را روی سایت بارگذاری کنید. تا وقتی Perfmatters فعال است، محافظ ورود قالب **خاموش** می‌ماند و هیچ تغییری حس نمی‌کنید.
۲. یک بار وارد پیشخوان شوید (از `/secret-door/`). قالب نشانی ورود Perfmatters را برای خودش ذخیره می‌کند.
۳. در **افزونه‌ها**، Perfmatters را **غیرفعال** کنید (هنوز حذف نکنید).
۴. **در یک پنجره ناشناس (Incognito)** این‌ها را امتحان کنید:
   - `https://psb.co.ir/secret-door/` باید فرم ورود وردپرس را نشان دهد و ورود باید انجام شود.
   - `https://psb.co.ir/wp-login.php` و `https://psb.co.ir/wp-admin/` باید صفحه ۴۰۴ سایت را نشان دهند.
   - صفحه اصلی، فروشگاه، تماس با ما، استعلام قیمت و `/login/` باید عادی باز شوند.
۵. اگر همه درست بود، Perfmatters را **حذف** کنید. اگر مشکلی بود، فقط Perfmatters را دوباره فعال کنید؛ همه‌چیز مثل قبل می‌شود.
۶. اگر از کش (Cache Enabler / LiteSpeed) استفاده می‌کنید، یک بار کل کش را پاک کنید.

## ۵. سبک‌سازی‌ها (performance.php)

این بخش‌ها فقط وقتی کار می‌کنند که Perfmatters غیرفعال باشد:

| مورد | توضیح |
|---|---|
| jQuery Migrate | فایل اضافه jQuery Migrate (۱۳٫۵ کیلوبایت) در فروشگاه، محصول و تماس دیگر بارگذاری نمی‌شود |
| ردیابی منبع سفارش ووکامرس | `sourcebuster.js` و `order-attribution.js` (حدود ۱۸ کیلوبایت) در صفحه‌های فروشگاه حذف شدند |
| CSS مخصوص IE11 فرم‌ها | فایل IE11 فرم‌های Gravity Forms حذف شد |
| CSS ویدیو (ARVE) | فقط وقتی بارگذاری می‌شود که در صفحه ویدیو باشد |
| Google Fonts | اگر افزونه‌ای فونت گوگل اضافه کند حذف می‌شود (سایت از فونت محلی «پیدا» استفاده می‌کند و گوگل از ایران گاهی در دسترس نیست) |
| پاک‌سازی هفتگی دیتابیس | هر جمعه حدود ساعت ۴ صبح |

پاک‌سازی هفتگی دیتابیس فقط این موارد را پاک می‌کند:

- transientهای منقضی‌شده
- نسخه‌های قدیمی (revision) بیشتر از ۱۵ نسخه آخر هر نوشته
- پیش‌نویس‌های خودکار قدیمی‌تر از ۷ روز
- دیدگاه‌های هرزنامه و زباله‌دان قدیمی‌تر از ۳۰ روز
- متای نوشته‌های حذف‌شده

نوشته‌ها، سفارش‌ها، محصولات و تنظیمات دست نمی‌خورند. گزارش ۱۲ اجرای آخر در گزینه `psb_db_cleanup_log` ذخیره می‌شود.

برای خاموش‌کردن هر مورد، در فایل یک افزونه کوچک یا `functions.php` بنویسید (نام‌ها: `jquery_migrate`، `order_attribution`، `gf_ie11_css`، `arve_css`، `google_fonts`، `db_cleanup`):

```php
add_filter( 'psb_perf_db_cleanup', '__return_false' );
```

خاموش‌کردن محافظ ورود بدون wp-config:

```php
add_filter( 'psb_login_guard_enabled', '__return_false' );
```
